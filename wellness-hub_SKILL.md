## §1 Project Identity & Design Philosophy

**One sentence:** Wellness Hub is a production-grade, self-hostable clone of the student-wellness reference app EvolveWell (`https://evolve-well-d6cec85d.base44.app/`) — 11 modules (dashboard, routine templates, exercise, mood journal, assignments, events, study resources, reminders, learning, goals/achievements, profile) with a deliberate functional superset.

**Design thesis:** *parity-first, computed-style-probed*. The reference's visuals are the contract — every color, shadow, blur, and font was live-probed via computed styles and DOM reads (never eyeballed), then pinned in `@theme` with the probe evidence in comments. The look (the reference's 2026-10-30 redesign, WH-15): a per-module gradient identity — every page carries its own H1 gradient, button pair, page-root wash (`from-<m1>-50 via-white to-<m2>-50/30`) and container width — over the BRAND family's 135deg indigo→purple pair (`#6366f1`/`#a855f7` on the wordmark, badge, gradient active pills, mobile/drawer titles; the only preset-themeable surfaces). White `border-none shadow-lg` cards with 5%-opacity gradient washes + `rounded-2xl` gradient icon tiles; the gradient active pill on BOTH the desktop sidebar and the drawer; the shell's two washes; the monochrome slate login; and the glassy `md:hidden` mobile header + Radix Sheet drawer.

**Non-negotiable rules:**
- **Parity before superset.** Match the reference exactly; add functionality (auth ladder, theming, achievements, export, SEO) only where the reference lacks it.
- **The login wall is the root face.** Logged-out `/` → `/login` (the reference serves its auth screen at the root); no marketing layer.
- **Anti-generic within parity:** the brand pair comes only from tokens; no hardcoded hexes in components (the pastel tiles carry authored inline tints decoded from the reference — those ARE the parity data, not drift).
- **Degrade, never fail.** Optional integrations (Google OAuth without credentials, placeholder video URLs) answer honest "not configured" toasts and new-tab opens, never 500s.

**Verification:** an agent reading §1 alone must refuse to add a marketing landing page, a second nav genus, or an unpinned color — that is the test.

## §5 Component Architecture & Patterns

**The layer model (the Golden Rule: data flows DOWN from the API through the store into components; events flow UP through store actions; nothing skips a layer):**

```
Layer 0  Content data      prisma/seed.ts + Badge/RoutineTemplate/Tutorial tables — DATA, never components
Layer 1  Pure seams        src/lib/wellness.ts (streaks/points/badges/status/codec), password.ts, format.ts — node-safe, Vitest-pinned, NO store/prisma imports
Layer 2  Server surface    src/app/api/* handlers + src/lib/{auth,api,badges-server}.ts — requireSession → parseBody(zod) → ownership → prisma → ok()/fail(); badges award HERE
Layer 3  Client stores     src/stores/{wellness-store,theme-store}.ts — the ONLY fetch path (call()); actions refresh affected slices
Layer 4  Components        src/components/{layout,shared,ui} + page shells — thin; plain data into Layer 1 helpers; dialogs remount forms via key
Layer 5  Routes            src/app/(app)/* dual-case pages + auth pages — aliases only re-export; NO logic
```

**Directory map:** `src/components/layout/` (8 files — app-shell, sidebar, mobile-nav, nav-config, login-card, guest-login-redirect, reset-password-screen, theme-boot [the root-layout mount carrying the chosen mode onto the login family, WH-18]) · `src/components/shared/` (the cross-module page-parts: stat cards, dialogs, calendar, star rating) · `src/components/ui/` (the six live primitives: dialog, input, label, select, tabs, toast — Radix rides dialog/select/label; the ui-module census pin in `tests/route-census.test.ts` locks the set; the seven CRM-era modules avatar/badge/button/card/dropdown/icons/table retired at WH-4). 46 .tsx files total; 27 are `"use client"` (the interactive leaves + shell).

**Client vs server decision:** RSC by default; `"use client"` only where interactivity demands it (dialogs, forms, the drawer, the theme boot). The `(app)` layout is a server component that reads the session and redirects; everything below it that mutates is a client island talking to the store.

**Auth pattern:** `requireSession()` (never raw cookie reads) inside every handler; `isGuarded(guard)` narrowing; the `(app)` layout as the page-level wall — handlers enforce independently (defense in depth).

## §6 Custom Hooks Deep Dive

This codebase has NO custom hooks directory — the reactive seams are the two Zustand stores, and that is the deliberate pattern:

- **`useWellnessStore`** (`src/stores/wellness-store.ts`, ~600 lines): ALL server state, one store, sliced by module. `hydrate()` is called ONCE by `AppShell` on mount; `call()` is the only sanctioned fetch path (adds `credentials: "include"`, unwraps the envelope, throws `EnvelopeError` on `!ok`, refreshes the affected slice after mutations). Why: an 11-module app with per-route fetches drifts on error handling within a week; one `call()` keeps the envelope greppable and the toasts uniform.
- **`useThemeStore`** (`src/stores/theme-store.ts`, ~200 lines): writes `--color-primary`/`--color-secondary` (plus derived hovers via the private `shade(hex, 0.88)` helper) directly on `<html>` — ONE write re-skins every gradient surface because all v4 utilities compile to `var(--color-*)`. Persists to localStorage (instant pre-hydration render) AND fire-and-forget PUTs `/api/prefs` (`fetch(...).catch(() => null)` — the local state never waits on the network). Toggles the `.dark` class.

**If you find yourself writing a `useX` hook:** first check whether the logic belongs in `src/lib/wellness.ts` (pure — preferred), the store (server state), or the component (trivially local). A new hook file needs a story for why none of those three fit.

## §12 Lessons Learnt & How to Avoid Them

1. **Probe, don't eyeball (WH-1).** Every visual pin came from computed-style reads and byte extractions of the live reference. Eyeballing produced zero of the @theme values. → When touching any visual surface, re-probe the reference first (`agent-browser eval getComputedStyle(...)`).
2. **The reference itself has defects — match deliberately, not blindly (WH-1).** The reference's own sidebar text renders below the 900px fold on its deploy; its signup button 404s; its video URLs are placeholders. Each was decoded, documented, and deliberately improved or mirrored — the deviations live in the PAD's known-issues ledger. → A deviation nobody wrote down is a bug nobody can defend.
3. **Rebrand sweeps need filesystem-scan pins (WH-2/A-6).** The signup title survived a whole-domain rebrand because no test scanned for it. → Pin the INVARIANT ("src/app contains no NEO CRM string"), not the instances.
4. **Count the things (WH-2).** The docs said 41 e2e; the tree ran 42 (the setup project was never counted). → When a count changes, `rg "<old>"` the whole doc set in the same commit.
5. **The chassis was the right call (WH-1).** Replacing the CRM's domain on its auth/envelope/db-path/shell chassis (457 files, +9,147/−105,780) shipped in one round precisely because the infra was already pinned. → Port battle-tested seams; don't rewrite them.
6. **The override mechanism beats the update for transitive advisories (s198, inherited).** `bun update dompurify` hoisted the root AND left a nested vulnerable copy; `overrides.dompurify` in `package.json` + a clean reinstall reproduced the lockfile exactly. → Transitive fixes ride overrides + pins, never ad-hoc updates. (WH-3 coda: when the chain's root consumer turned out to be a dead dep, the override retired WITH it — the deeper rule is the census: no package without a live import, then the override question never arises.)
7. **Rate limits shape test architecture (A-8).** The per-IP login limiter forced the storageState doctrine. → Design test fixtures around your own security posture, not against it.
8. **A dependency is a doc claim (WH-3).** Six packages shipped three rounds with zero imports while five docs claimed their features (charts, PDF export, property tests, axe teeth) — the WH-1 domain replacement deleted the CRM's csv/pdf-export seams but left their packages, and every doc inherited the claim. → The census pin (`tests/dead-deps.test.ts`) makes the dependency tree a TESTED contract: a package without a live import fails the gate, and its doc claims die with it. Never write a feature row for a package the tree does not import.
9. **Count claims need a pin, not a proofread (WH-5).** The wrong model-count heading (a "14-models" claim) lived in all five docs through four audit rounds while the schema had 15 — and every doc's OWN ENUMERATION listed 15 items under the wrong heading; nobody counts another writer's list. The same round found three more stale technical claims (a dead primitives list, a wrong blur attribution, a z-map naming a z-40 layer no class uses). → The docs-counts pin (`tests/docs-counts.test.ts`) computes what the tree can count and fails `bun run test` on any doc that stops carrying the canonical claims: proofreading is not a gate, a pin is.
10. **Citations and exports are surface too (WH-6).** Ten dead coercion helpers shipped five rounds narrated as "surviving on the URL-param surfaces" — defended by a comment citing a test file that never existed, while zero routes parsed URL params at all; four POST handlers shipped a duplicated unreachable `return` that no gate flagged. → A comment defending dead code with nonexistent files is a maintenance lie: the src-surface census pin (`tests/src-census.test.ts`) makes cited-test-path existence, the api.ts export surface and statement hygiene TESTED contracts — the same doctrine that pinned the dep tree (WH-3), the route/ui surface (WH-4) and the docs' counts (WH-5).
11. **Tests pin modules; they do not keep them alive (WH-7).** An entire CRM-era format subgraph — money formatters, relative-time labels, a calendar grid duplicated by wellness.ts monthGrid, and the date primitives feeding only itself — survived six rounds BECAUSE tests pinned it: the checks narrated CRM surfaces ("the reports uppercase-K variant", "the Sales Target formula") that never shipped in this domain, and 15 more dead exported values plus a dead CSS @utility shipped alongside. → A test that pins dead code is a live-looking lie; liveness is a property of PRODUCTION consumers. The exported-value + CSS-utility census (the src-census pin's WH-7 extension) walks export sites so the class cannot return — and when retiring test-pinned surface, land the live twins' pins FIRST (the three live formatters had shipped unpinned; their pins and the retirement landed in one commit).
12. **Word-grep liveness censuses lie in both directions (WH-8).** The store carried a write-only `user` field for four rounds and a dead `prefs` slice — invisible to any word-boundary census because "user" is everywhere and "prefs" lives in the theme test's prose and the route census's API-family list (fake consumers), while a grep for member names would also have "flagged" nothing real. The ui layer carried seven dead re-exports because the WH-7 value census read only `export const/function` declarations — the `export { … }` blocks were invisible. → Liveness censuses must read the CONSUMPTION SITES (destructures + selectors at `useWellnessStore` call sites, export-block names), not word occurrences; and a same-module data feed cures by dropping the `export` keyword, keeping the code. The advisory posture went to ZERO the same round — versions are offline-readable lockfile facts, so the posture is a TESTED contract (`tests/dead-deps.test.ts`), not a doc claim.
13. **Props are a census class of their own (WH-9).** The dead `underline` default arm hid inside tabs for eight rounds BEHIND A LIVE PROP — the ui-export census saw the export name, the value census saw the constants, the store census saw WellnessState; none of them saw the surface between them (a component's ACCEPTED props). The theme store's dead `reset` rode the same gap (the WH-8 census walked WellnessState only), and SidebarNav's `onNavigate` survived on a comment narrating a drawer sharing that never existed — the comment was the prop's only consumer. → Pin the surface at the DESTRUCTURE (the api-export-surface doctrine: drift trips in either direction); a prop with one possible value carries no information — collapse it; and when a comment is a prop's only justification, the comment cure and the retirement land together. Known census boundary, documented: fields nested inside a prop's TYPE (the tabs item's former `count`) ride no census — widen when a finding lands in the gap.
14. **A pin's blind spots are finding classes of their own (WH-10).** The docs-counts pin held the TOTAL (314, lockstep-enforced) for five rounds while the §8.1 infra row above it drifted 22 checks stale — WH-7's retirement decremented the total but nobody recomputed the row, and three subsequent rounds hand-incremented the wrong base; a distribution table whose rows don't sum is a lie with a true bottom line. The same round caught the compound spelling: the hyphenated fourteen-models phrasing lived in PAD §3.2/§12 through the WH-5 cure and the forbidden-forms list, because the list's spaced and spelled-out entries don't match the hyphenated compound. → Pin the ARITHMETIC, not just the totals (rows must sum to the canonical counts — a legitimate redistribution never trips it, arithmetic falsehood always does); and forbidden-forms lists must cover the compound spellings a false count hides in — but pinned at the drift PHRASE, never the bare prefix, because the flat substring scan cannot distinguish history (or this very lesson) from live claims: a doc cannot QUOTE a forbidden form, so the narration must describe it without spelling it.
15. **Census regexes see only the declaration forms they were written for — and a census must never consume its own narration (WH-11).** The type-declaration surface (`export type`/`export interface`) sailed through five census-extension rounds because every pin read value declarations (`export function/const`), export-block names, or member accesses — a dead hand-written domain interface (the orphan of a retired store slice) and twenty same-module-only exported types lived inside the gap. The audit's first census pass ALSO missed five of the twenty because it counted the src-census pin's own machinery text (which names the store-state and envelope types) as consumption — a census that counts its own narration as consumption guards nothing. → Extend liveness censuses by DECLARATION FORM, not just by module (a whole-tree walk beats a fixed list wherever framework contracts don't force the list); always exclude the pin's own file from its corpus; and a same-module-only TYPE cures by dropping the `export` keyword, keeping the declaration — the data-feed doctrine's type form.
16. **A surface pin is not a liveness pin — pin the PASS SITES, and draw the stock-API boundary explicitly (WH-12).** The WH-9 prop census pins the destructured SHAPE of a fixed ten-component set (drift trips in either direction of the shape) — but a prop can sit pinned as "live surface" for three rounds while zero call sites ever pass it: GradientButton.className rode inside the pinned set, and Checkbox carried four invented props feeding an uncontrolled arm and a label-render arm no caller ever exercised. The fix pins what callers actually WRITE: the whole-tree JSX pass-site census (a prop is live when some call site — same-module included — passes it), with the exemptions the doctrine draws explicitly: `children` (JSX-nested), byte-stock shadcn wrapper signatures (the L-71d4 hideClose retirement's own justification — "not stock shadcn" — implies stock signatures keep their shape; the never-customized stock props live in a pinned allowlist, a conscious keep), and Next.js convention files (framework-rendered props, the export-default doctrine). A spread attribute passes everything (the conservative reading — the census never false-positives; it can only miss dead props hiding behind one, and the tree has zero app-level spreads). → When pinning interface surface, ask what the pin actually proves: a shape pin proves the signature didn't drift; only a consumption pin (importers for exports, passers for props, readers for members) proves the surface is alive — and the boundary between "stock API shape" and "invented surface" must be written down, or every future audit re-litigates it.

17. **Writes do not keep a column alive — the consumption verb for a COLUMN is the READ (WH-13).** Four `completedAt` columns shipped thirteen rounds: written at every completion seam, declared on the payload wire, read by nobody — invisible to every TS/TSX census because none of them reads the DATA layer. `Tutorial.views` rode the same gap one level deeper: never even written (the `@default(0)` fills it), and it turned out to be the REFERENCE's own dead-weight field (its entity API returns `views:0` on all 12 tutorials, its UI never shows it) — the parity-first doctrine mirrors it as a conscious keep (the SCHEMA_PARITY_KEEPS list, the STOCK_ALLOWLIST's schema mechanism), exactly like the Watch-Video placeholders. → The census pins READ sites only (a component occurrence, a `.field` access, a query-context key): a write expression is authorship, not consumption — the WH-8 write-only doctrine's column form. And the stock boundary in a schema is the DIRECTIVE, not the name: `@updatedAt` (and any reference-mirrored field on the keeps list) is a conscious keep; an undirected column is invented surface and needs live readers. The census also taught its own lesson mid-landing: JSX comment blocks (`{/*`) count as occurrences unless the comment filter covers them — a census's comment exemption must match the file type's comment FORMS.

18. **A design token is a declaration like any other — and the compiled stylesheet is not a liveness oracle (WH-14).** The `@theme` block carried 59 dead tokens through fourteen rounds: 44 v3 palette re-pins whose classes left src/ in later rounds (the pins outlived their surfaces), a `--color-sidebar-accent-foreground` WRITTEN by the theme store on every preset apply and read by nobody (the WH-8 write-only doctrine's token form — a `setProperty` call is authorship, not consumption), the never-read `sidebar-active`/`line-strong`/feedback-soft set, three radius tokens, and two animate tokens whose "Animations for Radix primitives" comment was stale the day the vendored tw-animate.css took the job. Meanwhile the compiled stylesheet GREW: Tailwind v4's automatic content detection scans every tracked file, so the `skills/` catalog's Tailwind examples were compiling too — 1,013 of 1,419 selectors (71% of 160 KB) were markdown-born dead weight, invisible to every capture round because never-rendered CSS moves zero pixels. → The consumption verb for a TOKEN is the utility (a class string in app source) or the `var()` read; the census's corpus is app source ONLY — the compiled sheet carries every declared token's name in its `:root` dump (a compiled-presence test false-passes) and every markdown-mentioned class (a compiled-selector test false-passes). The source scan is pinned with `@source not` (exclusion, not allowlist — the surgical form), and the palette contract is enforced in BOTH directions: a used pair without a pin trips the completeness check (the surface computes the v4 re-derived default instead of the reference's own v3 value — a live-probed drift), a pinned pair without usage trips the token census. And the round's capture lesson: byte-stability is the rule only for zero-pixel rounds — the 19 missing pins were a parity FIX, and the movers were predicted in the plan before the md5 ledger proved them.

19. **A reference is a moving target — watch the asset hash, and when the deployment changes, re-probe the computed styles, not the DOM text (WH-15).** Fourteen rounds of "zero new surfaces" were true at the TEXT layer while the reference quietly redeployed a full visual redesign: its stylesheet moved `index-eZhxKCJC.css` (907 KB) → `index-heGLHP2e.css` (89 KB), and with it every page gained a per-module gradient identity (H1 stops, button pairs, page-root washes, containers), the desktop active nav became the gradient pill, the brand family turned 135deg, the stat tiles went white-card-plus-gradient-wash, the login went monochrome slate — while every title, label, seed row and API shape stayed byte-identical. The watch classes caught it ONLY because the compiled-CSS watch diffs the ASSET HASH, not the content: a text-surface probe (titles, labels, seeds) sees nothing, and a pixel capture of OUR app sees nothing either (it pins OUR state, not the reference's). → Treat the reference's asset hash as the deployment-change signal; on a hash move, walk the computed styles of every page (gradients, washes, geometry — `getComputedStyle(...).backgroundImage` + element widths), and pin the new identity as a MAP (`PAGE_THEMES`), not as scattered literals — the census then enforces coverage, pin-completeness and consumption structurally. And the theming-model probe matters as much as the colors: the redesign split the surfaces into preset-themeable (brand) and fixed (module) — a distinction no static analysis can recover, only a live preset toggle can. **And a preset probe that SAVES changes the account (the WH-16 coda):** WH-15's Ocean Blue toggle outlived its round — the revert never saved, so the next round's first probe read a sky/cyan brand family on a "clean" baseline. Probe protocol: read the account's CURRENT preset before probing (a non-default state is residue, not drift), and after any preset experiment apply the revert AND verify the save took.
20. **The console is a surface the gate never read — an error class can ship for fifteen rounds behind green checks (WH-16).** The theme store's `onRehydrateStorage → applyTheme` writes client-only attributes onto `<html>` at store-module init; when module-eval wins the race against hydration (the cold-compile window), React 19 logs a hydration mismatch naming exactly those attributes — observed ONCE in ~50 loads, never in the Playwright probes (fresh contexts, stored presets, 8× CPU throttle, dev AND production builds), invisible to every e2e assertion because assertions see the DOM, not the console. → The net and the cure are different artifacts: pin the CONSOLE as an assertion surface (the e2e console-hygiene net — zero errors/warnings on the walked routes; a "benign" warning gets cured or pinned as a documented ignore entry, never silently allowed), and cure the WRITER with the canonical one-attribute fix (`suppressHydrationWarning` on the pre-hydration write targets — the next-themes pattern; element-scoped, children keep their checks) pinned by the static census. A timing-race error is still an error — "it doesn't reproduce" is a property of the harness, not of the bug.

21. **Accessibility is the console's twin — a semantics layer the gate never read, and a stale capture is invisible to pixel parity (WH-17).** The docs claimed WCAG AA for sixteen rounds while zero tests read semantics: every rendered chip failed AA (emerald-600 on emerald-50 = 3.58:1, amber-600 on amber-50 = 3.07:1), the Watch-Now labels violated Label-in-Name, the theme-mode chips failed at 3.71:1 — all shipped behind a fully green gate AND a pixel-parity capture discipline, because the captures pin OUR pages (our chips rendered "correctly" per OUR stale vocabulary) and the WH-15 redesign probes walked H1s/buttons/washes but never the chip layer. The vocabulary was a build-era capture ("decoded live from the reference's DOM" 2026-10-29) that the reference's OWN redesign had silently moved on: its chips became the Badge anatomy with `-100/-700` pairs that ALL PASS AA. → Run the a11y walk on BOTH apps (the reference's own state is the parity ledger: its tab strip fails AA exactly like ours did — the superset decision needs that evidence); re-capture divergent surfaces as MAPS (three of our six Learning category families were wrong, the difficulties were untinted on the reference, and the easy/moderate pair switched families entirely — no single-color tweak recovers that); and pin the net (axe at the claimed conformance level, zero violations, the ignore-entry doctrine) so the NEXT stale capture or AA regression cannot ship behind green checks. A pixel-identical clone can still fail the accessibility claim its docs make.
22. **A rendered state is a surface the gate never read — walk every flippable state, and read the compiled stylesheet as the oracle for variant-strategy bugs (WH-18).** Dark mode shipped broken through seventeen green rounds: the docs narrated class-based dark, the tokens flipped on the class, but every `dark:*` utility compiled to the `prefers-color-scheme` media query (Tailwind v4's default) — so a mode=dark user got light text values on dark cards (138 axe violation nodes), and an OS-dark user in light mode got gray-400 on WHITE cards without touching a setting. Every net, every capture, every e2e walked light mode only — the state a user flips in one Profile click was never an assertion surface. The compiled bundle had shown the bug all along (`@media (prefers-color-scheme:dark){.dark\:…}` wrapping every dark utility). → Enumerate the FLIPPABLE STATES (modes, presets, OS preferences, viewports) and walk each with the same nets; read the compiled stylesheet when a variant family misbehaves — the strategy is visible in the bundle; and never let a comment narrate a mechanism that has no code (the auto-mode "listener stays attached" comment narrated a listener that did not exist).

23. **The net walks what it knows — the walk set is a surface of its own; and an axe "incomplete" is not a pass (WH-19).** The WH-18 dark walks covered the routes their author knew about — and the surfaces OUTSIDE the walk set shipped with the same broken class: the signup view's title computed 1.0:1 on the dark card, the login subtitle 3.77:1 with axe FALSE-PASSING it (the alpha card over the page gradient returns color-contrast incomplete — not a violation, so the net stayed green with a real AA failure on the page), the 404 a full light island. And the deepest catch of the round: the 404's pathname span was the app's one SSR/client hydration mismatch — usePathname on the SERVER for an unmatched route returns Next's internal "_not-found", so the SSR showed the meaningless internal route name, React #418 regenerated the whole tree on the client, and the regeneration's patch DELETED applyTheme's pre-hydration writes off <html> (the .dark class, the preset style block, the data attrs — MutationObserver-caught: written at t≈150, deleted at t≈200). A pre-hydration write that survives hydration on TEN pages can still be deleted on the eleventh — the mismatch is per-PAGE, and the page nobody walked was the one that broke the theme. → Enumerate the WALK SET itself as a surface (which routes/states does the net NOT cover — and why); when axe returns incomplete on a real text surface, MEASURE it (the computed-contrast leg, oklab-aware); catch hydration mismatches at the page level (a #418 anywhere can delete pre-hydration writes everywhere in that tree); and pin the preset axis as a TABLE (all 8 measured — the WH-18 ledger had documented only the worst single patient).


24. **The interaction states are a surface the gate never read — and a computed-style probe of a transitioning property reads t≈0 (WH-20).** Axe never hovers, never focuses, and the state walks render resting pages only — so three defect classes shipped behind fully green nets through eighteen rounds: the login family's dark focus rings were PAIRED (the WH-19 census verified every arm carried its dark twin) while the twin's VALUE sat at 2.29:1 (pairing is not contrast — a census proves the arm exists, only arithmetic against the rendered surface proves it can be SEEN); the toast's hovered dismiss glyph rendered 1.05:1 exactly when the user aimed at it (its resting state passed at 7.0:1 — the only broken state was the interactive one); APP_FOOTER was a white strip on every dark page that every walk passed because its self-contrast is AA-fine (axe reads ink-vs-own-bg — the light-island class, the 404's twin, on the most-travelled surface of all). The empty-list walk gap: the dark e2e walks render the demo account's EMPTY module lists, so the ROW surfaces (delete buttons, chips, the complete-circle) never render in any walk — the data-bearing leg creates its row through the API with the storageState cookie. → Pin the interaction axis with BOTH layers (the census for the arm's EXISTENCE, the arithmetic pin for its VALUE, the e2e legs for the live state); drive :focus-visible with REAL keyboard Tab (program focus() does not match it after mouse use) and :hover with a REAL pointer event (synthetic mouseenter never sets it); and SETTLE before every computed-style read of a transitioning property — `transition-all` interpolates box-shadow from five transparent zero layers, so a synchronous read returns the t≈0 frame and false-flags a healthy ring as invisible (≥400 ms settles it; the first dark-walk numbers for the Profile chips were exactly this artifact). The reference's own focus states are the parity ledger's evidence: its keyboard focus is INVISIBLE (transparent outlines, no rings) — our focus-visible superset is the whole point of the divergence.

25. **The delivery mechanism is an assertion surface of its own — probe the MODALITY, not just the content (WH-21).** The reference's seven module create-forms are inline expanding cards in the page flow; ours shipped as 512px Radix modal overlays through twenty rounds — while every probe, every e2e locator and every capture read the forms' CONTENT (the field sets were parity all along) from INSIDE the opened overlay. Nobody ever asked what the overlay itself was: the fixed layers, the scroll lock, the position. The e2e battery even pinned the wrong modality in passing (`getByRole("dialog")` locators — tests can encode the bug they should catch). The same round found the mood-selector pills riding the preset-themeable `primary/10` model when the reference's own active tile is its FIXED blue→cyan pair — the wrong THEMING model invisible to every content probe that read only geometry. → When parity-checking a surface, enumerate the DELIVERY axes (overlay vs in-flow, scroll lock, width, position) alongside the content axes; pin the modality structurally (a census: no dialog import, the FORM_CARD record consumed) and live (an e2e leg: no `[role=dialog]`, ancestors static, body not scroll-locked); and beware the class-string trap — `BUTTON_CLASSES`' `inline-flex` + `transition-colors` fight a block-stacked `transition-all` tile, so a self-contained string beats composing a shared record the anatomy never fit (every other consumer stays byte-identical).

26. **The surface your probes keep skipping is the one you open to read something else (WH-22).** The Routines Schedule modal was opened by at least four rounds — WH-15 probed its overlay, WH-21 probed its modality, the e2e battery clicks through it every run — yet its CONTENT was never read field-by-field: the 672px width, the description living in a gradient TILE (not the header), the steps as gray-50 tiles with solid module-pair circles, the primary ALONE at w-full in the module pair. Every one of those members deviated while the flow "worked". The tell: a surface that is ALWAYS a means to another end (you open the dialog to test navigation, to test scheduling, to test modality — never to read the dialog) becomes a blind spot no walk-set enumeration catches, because it IS in the walk set — just never as the subject. → When a surface recurs across rounds as instrument rather than subject, schedule the dedicated read (open it, walk EVERY member's computed style + DOM in one visit, and pin the anatomy — a record + a census, so the read is never needed again); and probe the module-vs-category question explicitly (two templates of different categories — one probe answers whether a color is the module's identity or the item's).

27. **An identity probe reads COLOR; the GEOMETRY needs its own walk (WH-23).** The WH-15 redesign probe mapped every card family by its colors — the washes, the gradient pairs, the button pairs — and twenty-three rounds of green gates trusted the map. The geometry was never read: the Quick Actions grid ships 12px GAPS on the reference (not our border dividers); its cells are fixed h-24 whose hover is an ICON SCALE + a label lighten (never our bg wash + indigo icon — probed with a real pointer: the cell bg stays transparent through the hover); the reference's `[&_svg]:size-4` WINS the cascade over the svg's own w-6 h-6 (the icon computes 16px — a class-on-class specificity question only a COMPUTED read answers); every list card rides the CardHeader/CardContent anatomy (p-6, no border-b, the icon inside the title at inherited ink); the module KPI tiles carry big w-12 h-12 tinted icons ours never shipped at all; the empty states are bare paragraphs (no chip); and two pages OMIT their list sections at zero rows. Every one of those deviated while the COLORS were parity. → A surface mapped by identity is NOT field-verified: schedule the geometry pass per surface family (computed styles + DOM + a real pointer for the hover families — the resting read cannot see the interaction); read the COMPUTED size, never the class string (the specificity cascade decides); and pin the anatomy in records + censuses so the geometry map cannot rot the way the color map didn't.

28. **Parity is a property of the RENDERED FACE, not the data — and one family's walk opens its siblings (WH-24).** The reference's routines template DATA carries thumbnails and video URLs its UI never renders — our conditional branches (`{t.thumbnail && …}`, `{t.videoUrl && …}`) rendered them for six of eleven seeded cards, a visible deviation hiding behind truthy checks for twenty-four rounds while every content probe read the fields we both share. The same round's declared targets (the tutorial cards + the calendar card) opened four MORE families in the same probe visits: the module toolbars (hand-rolled `py-2 text-sm shadow-xs pl-9` search strings where the reference rides the stock Input + `pl-10` + a Filter-icon wrapper), the shared chip's stock Badge arms, the form textareas (`min-h-16/min-h-20` + text-sm where every reference textarea is byte-identical `min-h-[60px] text-base md:text-sm`), and the sibling card family itself. → Probe the FACE (count the rendered `img` elements, read the rendered class strings), not just the shared fields — a branch the reference never renders is a deviation however truthful its condition; and when a walk opens a family (the toolbar, the chip, the textarea), walk the whole family in the same visit — the sibling surfaces share the form by construction, and each one left unwalked is next round's blind spot. And when a shared record's arms differ between surfaces (the ROUTINE_CATEGORY_GRADIENTS 600 hover arms vs the module primaries'), probe BOTH consumers before changing the shared record — the reference itself runs different button families side by side (the module primaries darken their stops on hover; the template button is opacity-90 alone).
29. **A superset's premise must be probed, not assumed — absence claims need the surface OPEN (WH-25).** The WH-21 round cured the Profile checkboxes' dark state as a "pure superset" on the claim "the reference ships ZERO checkboxes, probed live" — but that probe never opened the Preferences tab; the live read shows NATIVE bare `input[type=checkbox] w-5 h-5` controls there. The CRM-chassis custom Checkbox, its dark-state cure, its interaction-contrast arithmetic pin and its a11y e2e leg all shipped on the untested premise through four green rounds — every one of them defensible-sounding, none of them checked against the actual surface. The same round's geometry walk found the whole tab region deviating (the wrapper, the panels, the swatches, the stack, the rows, the save bar) because the WH-17/18 color probes read the panels' COLORS without ever walking their fields. → An absence claim ("the reference ships zero X") is only as good as the surface it was probed ON: name the page, open the tab, count the elements — and when a superset's justification cites an absence, re-verify the absence before building on it. And the color-geometry split applies WITHIN a surface: a panel mapped by its washes is not a field-verified panel.
30. **A pin must assert the RENDERED LEAF, not the parent's arm — and a redeployment resets every standing map (WH-26).** The WH-21 F-3 pin asserted the active mood tile's `text-white` — the BUTTON's arm — while the label span's constant `text-gray-700` overrode it in the cascade: the ACTIVE label rendered GRAY on the blue gradient for five green rounds, through an anatomy census, an arithmetic pin and a dark-walk e2e leg, because every one of them read the class string on the parent (or its computed color on the button) instead of the rendered label's computed color. The same round's trigger is its own lesson half: the reference REDEPLOYED (the compiled-CSS hash moved `assets/index-heGLHP2e.css` → `/static/index-s8d1FO8M.css`), and with it the standing facts changed — `/signup` went 404 → 200-with-auth-wall-bounce, the sr form GAINED an upload field the WH-4 absence claim had ruled out, the reset flow began firing a real network request, and the toast viewport LOST `pointer-events-none` (the reference's own hamburger is now unclickable by real pointers — deliberately not mirrored). → When pinning a state-conditional surface, assert the LEAF the user sees (the label span's computed color, not the button's arm) — an arm pin proves the class is present, never that it WINS the cascade; and treat a moved asset hash as a full re-probe trigger: every absence claim, every "no network call" narration and every standing map is a hypothesis again until re-verified against the redeployed reference. And when classes move into a record (`MOOD_FORM`), the pins move with them — the record + the consumption site (the body-slice doctrine), never the page string alone.
31. **A probe's DECODER must match the reference's rendering vocabulary — and one site's family never generalizes to its sibling (WH-27).** The WH-26 round decoded the mood form's chip (an emerald SPAN) and applied it to the sr form — but the reference's sr chip is the stock Badge DEFAULT variant rendered as a **DIV** (an element-tag difference the WH-26 span-search could never see: the probe searched `span` elements, the chip was a `div`, so it "never rendered"). The same round's rating decode failed on the other axis: the reference's click fill renders the **⭐ EMOJI (U+2B50)**, and the probe's `☆/★` regex — a TEXT-GLYPH vocabulary — cannot match an emoji codepoint; the "inert click state" conclusion shipped in the ledger through three more WH-27 passes hitting the same trap before a full-HTML dump resolved it. And the F-5 false lead of the same round: the type-select trigger's `data-[placeholder]:text-muted-foreground` arm exists in the class but never applies (the select is SET, not unset) — the class string is not the rendered face. → Decode from the FULL HTML DUMP (the element tag, the child structure, the raw text — never a pre-filtered selector or a glyph regex); match the decoder's vocabulary to the platform's (emoji vs text codepoints, div vs span); and when a record serves two sites, probe EVERY consumption site before converting — the reference itself runs different families side by side on sibling forms, and a generalized cure is a deviation wearing a pin's clothes. When the decode finally lands, pin the SPLIT explicitly (the sr-chip census asserts the mood site keeps its own family — drift trips in either direction).

32. **A data-blocked surface is not a closed surface — and the reference's own bundle is an authoritative decode source (WH-28).** The WH-26/27 rounds recorded the mood list interior + the feed as "data-blocked at the platform level" (the reference's OTP is email-only, so no throwaway account can carry data) — and the block lifted TWO ROUNDS LATER without a redeployment: the shared demo account's own data changed (one mood row). The lesson has two halves. (1) A standing block is a HYPOTHESIS about the reference's state, not a property of it — re-check every standing block each round (the data on the SHARED account can change; a redeployment can ship in-app delivery). (2) When the live DOM shows a VALUE but not the FORMULA behind it (a stat tile reads "5.0/10" — is it toFixed(1)? floor? string concat?), the reference's own compiled bundle is the authoritative decode source: `/assets/index-*.js` is greppable through the minifier (`e.length>0?Math.min(7,e.length):0` — the "Current Streak" tile is entry-count-capped-at-7, NOT a consecutive-day streak; `(e.reduce((s,j)=>s+j.energy_level,0)/e.length).toFixed(1)` — Avg Energy's one-decimal format). The bundle decode also settled the feed's builder (three kinds, entity-date keys, cap 8) where the DOM at zero rows showed nothing. → Fetch the bundle (`curl <the compiled-CSS watch page's script src>`), grep for the surface's literal strings ("Current Streak", the tile labels), and read the formula from the minified context around them — then pin the decoded formula (the seam's spec) with the bundle provenance in the comment. And when one seam serves TWO consumers needing different formulas (the tile wants the reference's stub, the badge engine wants the real math), SPLIT THE SEAM PER CONSUMER (the WH-27 two-site doctrine, applied to consumers instead of sites) — never force one formula on both.

33. **The reference's ENTITY MODEL is decodable from its bundle — and a superset face shipped without a ledger row is a bug nobody can defend (WH-29).** The Goals Achievements section shipped as an always-on 8-badge catalog grid at WH-1, known-different from the reference's empty state since WH-17 (a code comment said so) — and survived TWELVE green rounds because the deviation lived in a comment, not the PAD §11 ledger. The WH-29 decode closed it: the reference's own bundle shows `Ue.Achievement.list("-earned_date")` filling the section — a PER-USER row table (its demo account carries ZERO rows; the empty state is the FACE, not a data gap) — and the full row template sat in the minified context one grep away the whole time. The bundle decodes more than formulas (lesson 32): it decodes the DATA MODEL (which entity a surface reads, what rows exist per user, what the zero state means) and the RENDER TEMPLATE (the element vocabulary, the variant arms, the conditional structure). → When a surface renders differently at what you believe is "no data", grep the bundle for the surface's strings and read WHICH entity it lists and WHAT the zero-length branch renders before concluding anything about the face. And the doctrine half: the superset is legitimate ONLY where the reference is missing functionality (the auth ladder, the theming engine) — where the reference HAS the surface, a different face is a deviation, and "Superset, never regression" demands every deviation carry a PAD row at ship time (the skill's own §1: "a deviation nobody wrote down is a bug nobody can defend"). A code comment is not a ledger row.

## §13 Pitfalls to Avoid

- **Don't add `tailwind.config.js`** — v4 CSS-first only; tokens live in `@theme`.
- **Don't remove any pin in `globals.css`** (the A-1..A-4 family + the v3 palette block + the dark overrides).
- **Don't "fix" the dual-case route folders** — the capitalized aliases are the reference's own hrefs; both families are e2e-pinned.
- **Don't resolve `DATABASE_URL` against `process.cwd()`** or inline an absolute path — the db-path seam is the contract.
- **Don't award badges or compute points client-side** — `src/lib/badges-server.ts` at the CRUD seams is the only awarding site (tamper-proof, testable).
- **Don't bare-`fetch` in components** — the store's `call()` is the only sanctioned path.
- **Don't import the store into `src/lib/*` seams** — pure means node-safe and Vitest-runnable.
- **Don't add per-test logins** in e2e specs (the limiter doctrine).
- **Don't loosen `noImplicitAny`, skip the smoke leg, or weaken a lint rule to ship** — a green gate achieved by weakening the gate is not a fix.
- **Don't hardcode emoji glyphs in components** — every vocab lives in `src/lib/constants.ts` as `OptionMeta[]` with the glyph as the label.
- **Don't un-ignore `skills/` in ESLint** — the catalog is the operator's, not app code.

## §14 Best Practices

- **TDD at the seams:** write the failing pin FIRST (`tests/*.test.ts`), then fix, then verify RED→GREEN on the record (the WH-2 flow: pin RED against the bug → fix → GREEN → full gate).
- **The envelope is the only response shape:** `{ ok, data } | { ok, error: { code, message } }` via `ok()/fail()/ERR.*` — greppable, uniform, testable.
- **Every mutation:** `requireSession()` → `parseBody(zod)` → `findFirst({ where: { id, userId } })` ownership check → prisma → `awardBadges()` at the seam → `ok()`.
- **Types:** `interface` for object shapes (the `src/types/index.ts` domain set), `type` for unions; strict mode; no `any`.
- **Comments explain WHY:** the file headers in this codebase carry the probe evidence and session history — keep that voice; don't strip it, don't write what-comments.
- **Docs in lockstep:** README, AGENTS, CLAUDE, PAD, SKILL, worklog — a behavior change that doesn't update its docs in the same commit is half-shipped.
- **Idempotent seeds:** content wipes + reseed; users UPSERT by unique key.
- **Secrets:** env-only; `AUTH_SECRET` fails hard in production; the smoke leg uses a throwaway secret so it's immune to the shell env.

**The guarded mutation handler (every body route copies this):**

```typescript
export async function PUT(req: Request, { params }: { params: Promise<{ id: string }> }) {
  const guard = await requireSession();                    // 401 via the envelope
  if (isGuarded(guard)) return guard.response;
  const { id } = await params;                             // Next 16: params is a Promise
  const parsed = await parseBody(req, workoutUpdateSchema); // 400 with a field message
  if (!parsed.ok) return parsed.response;

  const row = await db.workout.update({ where: { id }, data: parsed.data });
  return ok(row);
}
```

```typescript
export function currentStreak(dates: (Date | string)[], now: Date = new Date()): number {
  if (dates.length === 0) return 0;
  const keys = [...new Set(dates.map((d) => toDayKey(d)))].sort();
  const last = keys[keys.length - 1];
  if (dayDiff(now, last) > 1) return 0;      // forgiving: today OR yesterday keeps it live
  let streak = 1;
  for (let i = keys.length - 1; i > 0; i--) {
    if (dayDiff(keys[i], keys[i - 1]) === 1) streak++;
    else break;
  }
  return streak;
}
```
